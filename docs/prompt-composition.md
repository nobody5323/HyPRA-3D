# 提示词构成说明（Prompt Composition）

> 本文回答一个问题：**HyPRA 每一轮对话，实际写进提示词里的到底是什么。**
>
> 结论以代码为准（`backend/app/prompts/`、`backend/app/rag/prompt_manager.py`、
> `backend/app/graph/nodes.py`），文末附一段**真实渲染输出**（由当前代码跑出，非手写示意）。
> 关联文档：`docs/memory-architecture.md`（记忆四层）、`docs/st-preset-compat.md`（酒馆预设兼容）。
>
> **本次设计口径修正（2026-09-26）**：酒馆世界书不是每轮直接放进 `[背景设定]` / `[场景补充]`。
> 用户勾选的酒馆世界书先按角色卡作用域写入个人知识库（Qdrant / 内存实现），每轮通过
> 向量 + 关键词混合检索召回相关片段；酒馆会话则按用户勾选与预算同步。提示词不保留整本世界书，
> 只保留酒馆预设要求的会话消息，并在确实命中时追加检索得到的少量参考片段。
>
> **作用域修正（2026-09-27）**：酒馆世界书写入**酒馆专用作用域**（全局书 `tavern`、
> 角色内嵌书 `tavern:{persona_id}`），并且**只在 `tavern` 模式召回**——`companion` 模式
> 一个 `tavern` 作用域都不查。此前全局书写在共享作用域 `*` 下，桌宠模式的内置人设会
> 「知道」另一部作品的角色设定（实测被用户读成「召回坏了」）。键口径的唯一来源是
> `backend/app/memory/knowledge/scopes.py`，写入侧与检索侧共用，不各算各的。
> 代码仍保留旧的 `tavern_worldbook_enabled` 配置字段和返回字段用于兼容旧客户端，但它已不再控制酒馆世界书直注入。

## 0. 速览

| 项 | 现状 |
| --- | --- |
| 两种模式 | `companion`（桌宠对话，内置分层） / `tavern`（酒馆聊天，仅 ST 预设） |
| 组装分派点 | `graph/nodes.assemble_prompt` → `_assemble_builtin` / `_assemble_with_st_preset` |
| 内置模式最终 system prompt | 8 个分节，固定顺序（见 §2）；开启叙事框架层后多出第 0 节 |
| 总量预算 | 4000 token（`prompt_total_budget`），超出按优先级**逐层清空** |
| 必留层 | 只有 2 个：`角色人设` 与 `本次输入` |
| 预设数量 | 人设 3 张（陈小满 / 陆星野 / 苏澄）、文风 4 套（现代口语 / 简短利落 / 古典雅致 / 细腻长句）、叙事框架 3 档（默认关闭，见 §2.0） |
| 状态变量 | 3 个：`{{user_name}}`、`{{char_name}}`、`{{current_mood}}` |
| 结构化输出 | 强制 function calling，工具名 `report_reply_and_emotion`，8 类情绪 |

## 1. 两条组装路径

模式是**会话级属性**（切换模式 = 新建会话，`AGENTS.md §8.1`），因此一轮对话只会走其中一条：

| 模式 | 提示词来源 | 组装器 | 具身/桌宠层 |
| --- | --- | --- | --- |
| `companion` | HyPRA 分层提示词 + 本地世界书/记忆 + 检索结果 | `PromptManager.build()` | 启用 |
| `tavern` | 酒馆预设 + 角色卡 + 酒馆会话消息；酒馆世界书走知识库按需召回 | `render_st_preset()` | 关闭 |

酒馆来源采用两条**写入/读取链路**，不能混成「每轮直接注入世界书」：

1. 用户勾选的酒馆世界书 → 写入**酒馆专用作用域**（全局书 `tavern`、角色内嵌书
   `tavern:{persona_id}`），**只在 `tavern` 模式被召回**；
2. 用户勾选的酒馆会话 → 只同步预算内的会话轮次，用于长期回忆/会话上下文；
3. 每轮只对当前输入做向量 + 关键词混合检索，召回少量相关片段；
4. 提示词不放整本世界书，只放酒馆预设的会话消息，以及命中时的检索片段。

`insert_at_depth` 仍保留给**本地内置/自建世界书**的兼容路径；酒馆世界书的新流程不再依赖它。
`[参考资料]` / `[记忆回忆]` 只表示检索结果的承载格式，不表示把整库内容常驻塞入提示词。

## 2. `companion` 模式：system prompt 逐节写什么

最终 system prompt 由若干分节用**空行**拼接（`prompt_manager.build()` 第 ③ 步），顺序**固定**，与层优先级无关：

| # | 分节标题 | 内容来源 | 是否必留 | 默认预算 |
| --- | --- | --- | --- | --- |
| 0 | `[叙事框架：X]` | 叙事框架预设（**默认关闭**，关闭时该节不存在） | 否 | 600 |
| 1 | `[背景设定]` | 本地内置/自建世界书 `before_char` 档（**酒馆世界书不走此处**） | 否 | 与世界书共用 400 |
| 2 | `[角色人设]` | 人设预设正文（+ 可选 `[背景故事]`） | **必留** | 无上限 |
| 3 | `[场景补充]` | 本地世界书其余档位（**酒馆世界书不走此处**） | 否 | 与世界书共用 400 |
| 4 | `[可用技能]` | 技能清单（仅 id/名称/适用场景） | 否 | 400 |
| 5 | `[参考资料]` | 知识库混合检索结果：包括命中的酒馆世界书片段 | 否 | 900 |
| 6 | `[记忆回忆]` | 情景记忆 + 语义事实（包括按预算同步的酒馆会话记忆） | 否 | 各 400 |
| 7 | `【表达风格：X】` | 文风预设指令 + 模型适配 `style_hint` | 否 | 400 |
| 8 | `【回复格式】` | 输出形态（只说话）+ 字数上限 | **恒在**（形态恒开） | 不参与预算 |

### 2.0 `[叙事框架：X]`（放 system **最前**，可选层）

> 术语对齐 ST 的 `jailbreak` 槽位。设计说明见 **`docs/jailbreak-layer.md`**，此处只记落点。

**默认关闭**。不传 `jailbreak_text` 时该层为空串，system 提示与「这一层根本不存在」**逐字一致**
（回归测试：`tests/test_rag/test_prompt_manager_jailbreak.py`）。

开启后放**最前**：它是「这次对话处在什么框架里」的声明，必须先于人设与设定出现，
后面的内容才会被模型放在这个框架下解读。块内自带 `[叙事框架：X]` 标题
（与文风块同约定，`PromptManager` 不再额外加头）。

**为什么不放末尾**：ST 把 jailbreak 放在 `chatHistory` 之后靠临近输入施加强影响，
但内置路径只有**一条** system 消息，末尾已被 `【回复格式】` 占住；而框架层影响的是
「怎么理解后面的设定」，不是「这一轮说多长、要不要写旁白」。需要 ST 那种效果时走 ST 预设路径。

**只作用于内置分层路径**：ST 预设自带 `jailbreak` 槽位，再叠一层会变成两套框架打架，
且破坏 `docs/st-preset-compat.md` 的 §5–§7 组装契约。

三种传值语义（`state.jailbreak_id`，见 `nodes._resolve_jailbreak`）：

| 传值 | 语义 |
| --- | --- |
| 未传 / `""` | 用部署默认（`JAILBREAK_ENABLED`，出厂 `false` 即关闭） |
| `"none"` | 本轮强制关闭，覆盖部署默认 |
| 具体 id | 本轮显式指定档位，**同时隐含启用** |

### 2.1 `[背景设定]`（人设之前）

ST 的 `worldInfoBefore` 语义——**定义性设定**，排在人设之前，因此比「场景补充」更靠前、更根本。
每条命中渲染成 `[条目标题]\n内容`，多条之间空行分隔。

注意：这一块仅适用于本地内置/自建世界书的旧兼容路径。**酒馆世界书已经转成知识库文档，
不应再按 `before_char` 直接写入此块**；酒馆世界书只能在本轮检索命中后以参考片段形式出现。

### 2.2 `[角色人设]`（唯一永不裁剪的层之一）

内容 = 人设预设的 `prompt` 字段（`{{变量}}` 已替换），若该角色有背景故事，则在其后追加
`[背景故事]\n{background}`（见 `renderer.render_persona_background`；内置角色背景默认为空）。

写法约束（见 `app/prompts/authoring/persona.md`）：第二人称对模型说话、400–800 字、分 4–6 段、
必须写「不做什么」，不给专业诊断，不写破设定台词。

该文件是**通用人物设定模板**（题材/类型/关系由用户需求决定，不预设「陪伴」）：要求先定
「内核（一组矛盾）」与「独一份的具体细节」，并显式禁止形容词堆砌、现成脸谱与平均化输出。

### 2.3 `[场景补充]`

本项目**没有作者注槽位**，所以除了 `after_char`，ST 的 `ANTop/ANBottom`（作者注）、
`EMTop/EMBottom`（示例消息）三档也**降级并入**本块，并在 `warnings` 里记一笔
（`assemble._FOLDED_POSITIONS`）。`outlet` 档不进提示词。

### 2.4 `[可用技能]`

只有**清单**，没有正文——正文由 `study_skill` 工具按需取回（渐进式加载，`AGENTS.md §9.6`）。
每行格式固定为：

```
- {技能 id}：{技能名} —— {适用场景}
```

技能库为空时**整层跳过**（不注入空标题）。`study_skill` 工具也只在存在启用技能时才注册进 tools。

### 2.5 `[参考资料]`

个人记忆（用户主动上传/同步的语料，如酒馆世界书「同步到知识库」那条路）。每条前缀 `- `。

### 2.6 `[记忆回忆]`

两个子块，**相关回忆在前、已知事实在后**（`_render_memory_block` 的唯一实现）：

```
[记忆回忆]
相关回忆：
- {情景记忆召回}
已知事实：
- {语义事实}
```

两者都为空时整块不出现。

### 2.7 `【表达风格：X】`（放 system **最末**）

越靠近输入影响越强。内容 = 文风预设的 `instruction_block`（正向指令 + `避免：`禁令 +
示例声明）+ 空行 + 模型适配档的 `style_hint`。

### 2.8 `【回复格式】`（放 system **最末**，恒在）

内容 = **形态**（`DIALOGUE_ONLY_RULE`：只输出说的话，不写旁白 / 动作 / 神情 / 环境 / 心理描写）
+ **长度**（`一次回复不超过 N 字`，`reply_char_limit <= 0` 时只留形态）。

形态那条**恒开**，且**两种模式全局强制**（产品口径，与 `prompts/adaptation/rules.yaml` 的
`target.dialogue_only` 同源）。它原先只作用于「导入酒馆预设」的适配路径，内置分层路径完全没有——
于是默认文风下模型会自己补旁白动作（`*她轻轻笑了笑*`、`（他把杯子推过来）`、`心里想着……`），
把一对一陪伴写成念小说。文风预设管的是「怎么说话」，管不住「要不要写旁白」——那是形态问题。

放最末的理由与文风块相同（越靠近输入影响越强），而它排在文风块**之后**：形态比风格更贴近生成。
本层**不参与总量预算**（见 §3.2）——它是几十个字的固定约束而非内容，计进去会让「预算刚好够」
的配置连带把世界书 / 风格层裁掉。

`tavern` 路径不经过 `PromptManager`，由 `graph/nodes._assemble_with_st_preset` 在渲染与
`at_depth` 插入**之后**追加同一条约束（文案同一来源，不两处各写一遍；放在 at_depth 之后是为了
不让深度插入的锚点漂移）。`app/prompts/sanitize.py` 另做输出兜底，见 §11。

### 2.9 不写进 system 的部分（在 `messages` 里）

| 位置 | 内容 |
| --- | --- |
| system 之后、历史之前 | 文风预设的 **few-shot 示例对话**（真实 user/assistant 消息对，非文本） |
| 历史段 | 滚动窗口（`user: …` / `assistant: …`） |
| 最后 | 本次输入 |
| 按 depth 插进历史 | 世界书 `at_depth` 档（同 depth 同 role 合并成一条） |

> 示例对话单独放 messages 而非 system 文本，是因为模型对「真实消息对」的模仿远强于对指令的服从；
> 同时 `style.instruction_block` 里必须附一句声明，否则实测模型会把示例内容（如「我妈身体不好」）
> 当作用户的真实情况。

## 3. 预算与裁剪

### 3.1 默认值（`app/config.py`）

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `prompt_total_budget` | 4000 | 提示词总量 |
| `worldbook_budget` | 400 | 世界书注入块 |
| `knowledge_context_budget` | 900 | 个人记忆 |
| `memory_layer_budget` | 400 | 温层召回 / 冷层事实**各**按此预算 |
| `prompt_history_budget` | 700 | 滚动窗口 |
| `prompt_style_budget` | 400 | 文风块（示例对话取其中一半，下限 60） |
| `skills_budget` | 400 | 技能清单（`PromptManager` 构造参数） |
| `jailbreak_budget` | 600 | 叙事框架块（**默认关闭**，关闭时不占额度） |

这些值可在程序控制台按会话修改，改后立即生效（`api/chat.py` 会重建 `PromptManager`）。

### 3.2 两级裁剪

1. **层内预算**：每层独立截断（世界书/记忆块/历史窗口各自算），历史保留**最近**的消息。
2. **总量预算**：先丢最旧历史 → 再按优先级**从低到高整层清空**：

   `facts(55) → warm(60) → knowledge(70) → skills(75) → worldbook(80) → worldbook_before(85) → style(90) → jailbreak(92)`

   `persona(100)` 与 `user_input(100)` 为 `mandatory`，永不裁。
   `format(95)` 不参与总量预算（它承载输出形态与长度约束，是「形态」而非内容，
   见 `prompt_manager._total()`）；形态那条恒开，所以本层永远不为空。

   `jailbreak` 排在**最后**：默认关闭时它根本不存在，一旦被打开就说明是刻意选择，
   不该因为预算紧张被悄悄丢掉；被裁时会记一条 warning（否则「打开了破限却完全没生效」
   会变成最难查的一类问题）。

### 3.3 已知缺口（重要）

总量裁剪是**整层清空**（`layer.body = ""`），而 `persona` **没有上限**：

- 实测现象：人设一字未短、`total_budget` 仍被顶破，同时世界书/记忆/风格被逐层清空——
  用户看到的是「世界书莫名消失」；
- 根因：酒馆角色卡人设可达 ~5600 token，远超 4000 的总预算，而人设层无份额上限；
- 候选方案：**a1** 给必留层加份额上限（倾向）/ a2 逐层减半 / b 只调默认值。
  （记录于 2026-09-25 会话，尚未落地。）

## 4. 人设预设写什么

Schema 见 `app/prompts/persona/loader.py`（pydantic 强校验，缺必填字段直接报错）：

| 字段 | 用途 |
| --- | --- |
| `id` / `name` / `title` / `description` / `tags` | 元信息；`title`+`tags` 在 tavern 路径下充当 `charPersonality` |
| `prompt` | **人设正文**（进 `[角色人设]`，支持 `{{变量}}`） |
| `background` | 背景故事（进 `[背景故事]`，排在人设正文后、世界书前；可空） |
| `variables` | 声明用到的状态变量名 |

内置 3 张，刻意覆盖三种**相处方式**（证明「陪伴 ≠ 倾听」这条产品口径）：

- `therapist-elder-sister` 苏澄 · 心理倾听师（接住情绪）
- `energetic-roommate` 陈小满 · 拉你出门的合租室友（把人从房间拽出去）
- `sharp-tongued-partner` 陆星野 · 嘴上不饶人的搭档（拌嘴）

> 用户自建角色走同一套 schema，AI 扩写用的写作规范见 `app/prompts/authoring/persona.md`——
> 其中明确要求：**用户没提倾听/疏导时，不得默认写成心理咨询师**。

## 5. 状态变量（宏）

注册表见 `app/prompts/state_vars/definitions.py`，替换器见 `resolver.py`：

| 变量 | 默认值 | 含义 |
| --- | --- | --- |
| `{{user_name}}` | 朋友 | 用户称呼 |
| `{{char_name}}` | 角色 | 角色名（对话链路传入**本轮人设的真实名字**，兜底值才会出现） |
| `{{current_mood}}` | 平静 | 用户当前情绪（中文标签，由上一轮 function calling 产出） |

规则：命中运行时值 → 用值；未命中但有定义 → 用默认值**并记 warning**；完全未知 → 保留原文并记 warning
（不静默失败）。变量替换在**人设正文与背景**两处都生效。

## 6. 文风预设写什么

Schema 见 `app/prompts/style/models.py`。设计原则：**人设（谁）/ 文风（怎么说话）/ 模型适配（这模型吃哪套）三者正交**。

| 字段 | 用途 |
| --- | --- |
| `style_prompt` | 正向风格指令（为主，正向:负向 ≈ 3:1） |
| `avoid` | 少量必要禁令（只列最刺眼的 AI 腔，避免长串负面清单） |
| `examples` | 示例对话 2–3 组（反 AI 化最有效的手段，进 messages） |
| `sampling` | 建议采样参数（**可覆盖**模型适配档） |
| `conflicts_with` | 与人设冲突的特质（仅告警，不阻断） |

内置 4 套：现代口语（默认）/ 简短利落 / 古典雅致 / 细腻长句。
每套都带一句**强制声明**（实测必需）：

> （注：后续对话示例仅用于示范语气与句长节奏，示例中的人物与事件与用户本人无关，不得当作已知事实引用。）

## 7. 模型适配档的 `style_hint`

`app/llm/profiles.yaml` 为每个模型记一档**技术适配**（采样参数 / 推理开关 / 技术性输出约束），
按「界面显式选定 → 模型名子串最长匹配 → default」三级选择。文风预设的 `sampling` 覆盖本档，
本档独有的 `top_p` / `style_hint` / `enable_thinking` 保留。

`style_hint` 会被拼进风格块尾部，当前文本（Qwen / DeepSeek / default 三档基本一致）：

> 用纯文字说话：不使用任何格式标记（加粗、列表、标题、分隔线），也不使用表情符号与 emoji。
> 只输出对用户说的话；不要把思考过程、规则检查、自我纠正或「（注：…）」这类元评论写进回复。

推理型模型（Qwen3 等）默认 `enable_thinking: false`——情感陪伴场景不需要思考链，实测关闭后提速约 6 倍。

## 8. 本地世界书的兼容注入档位

下面是本地内置/自建世界书的兼容路径。**酒馆世界书不走这条直接注入路径**，而是先写入知识库，再通过混合检索返回少量参考片段。

按 ST 的 `world_info_position` 对齐（`app/prompts/assemble.place_worldbook`）：

| ST 档位 | 落点 |
| --- | --- |
| `0 before_char` | `[背景设定]`（人设**之前**） |
| `1 after_char` | `[场景补充]`（本项目原有的唯一位置） |
| `2/3 ANTop/ANBottom` | 无作者注槽位 → 并入 `[场景补充]` + 告警 |
| `4 at_depth` | 按 `depth` 插进对话历史（0 = 最后一条之后） |
| `5/6 EMTop/EMBottom` | 示例对话由文风预设提供 → 并入 `[场景补充]` + 告警 |
| `7 outlet` | 不进提示词 |

预算规则：**所有档位共用一份世界书预算**，但在**非空档位之间平分**——实测数据里
`before_char` 149 条、`at_depth` 70 条，先到先得的话前者会吃光整个预算。

深度插入有**地板**（`_anchor_floor`）：depth 再大也不会插到开头 system 段之前。

## 9. `tavern` 模式：ST marker → 内容映射

`render_st_preset` 复现 ST 的 `prompt_order` 组装语义。预设置位符（marker）由 HyPRA 运行时填充：

| marker | 填充内容 |
| --- | --- |
| `worldInfoBefore` / `worldInfoAfter` | 本地兼容世界书命中（人设前 / 后）；酒馆世界书不直接填这里 |
| `charDescription` | 角色人设正文 |
| `charPersonality` | 人设的定位 + 标签（近似） |
| `scenario` / `personaDescription` | 本项目暂无对应字段，默认空 |
| `dialogueExamples` | 文风预设的示例对话（多条消息） |
| `chatHistory` | 滚动窗口 + 本次输入（含 In-Chat 注入） |

其余关键行为：

- **自带正文条目**（`main` / `nsfw` / `jailbreak` / `enhanceDefinitions`）用预设原文；
  仅当 `use_sysprompt` 开启且提供了覆盖文本时才替换；
- **文风层追加到 `jailbreak` 位之后**，不覆盖预设正文；找不到 jailbreak 槽位则追加到末尾 + 告警；
- 酒馆世界书不作为整本内容进入 marker；它先同步到知识库，命中后的少量片段才通过 HyPRA 的知识/记忆扩展进入上下文；
- 用户勾选的酒馆会话才进入酒馆会话记忆链路，按用户设置的预算写入，未勾选或超预算的轮次不进入；
- HyPRA 记忆块若启用，作为「扩展注入」参与同层合并，默认 `IN_CHAT / depth=1 / role=system / order=100`；
- 宏（`{{char}}` / `{{user}}` / `{{setvar::}}` 等）按**会话**解析，未实现的宏保留原文并汇总告警；
- 历史消息正文**不过宏**（那是已发生的对话原文，改写会与界面记录不一致）；
- 未启用 `chatHistory` 槽位时，历史**追加到消息末尾**而不是凭空消失。

## 10. 工具定义也是提示词的一部分

每轮的请求里除 messages 外还带 `tools` 数组，其 schema 与描述同样占用上下文：

**情绪主通道**（强制，不可禁用——属 `core`）：工具名 `report_reply_and_emotion`，
参数 `reply`（必填）/ `emotion`（必填，8 类枚举）/ `intensity` / `confidence` / `evidence`。

8 类情绪：`happy` `calm` `sad` `anxious` `tired` `angry` `surprised` `neutral`
（→ 中文标签写入 `{{current_mood}}`，→ 3D 表情键驱动数字人，→ 记忆召回加权）。

**内置行动工具**（`app/tools/builtin_tools.py`，均带中文 `description` 作为选择依据）：

| 工具 | 触发时机（写在 description 里） |
| --- | --- |
| `record_mood_journal` | 用户表达了明显情绪时记录；**记录后要自然继续陪伴，不要生硬宣告「已记录」** |
| `query_mood_trend` | 用户问「我最近状态怎么样」「我是不是一直很焦虑」 |
| `start_breathing_exercise` | 焦虑 / 紧张 / 失眠 / 情绪激动；返回 `ssml` 交数字人示范节奏 |
| `recall_memory` | 需要确认「用户以前是否提过这件事」 |
| `study_skill` | **仅当存在启用技能时注册**（空库时是纯 schema 噪音） |

外部 MCP server 的工具按 `mcp__<服务器>__<工具>` 桥接进同一行动层。

## 11. 输出兜底（`app/prompts/sanitize.py`）

正向指令（`【回复格式】`层 + 文风预设）是第一道防线，本模块做最后兜底，
只删「被明确标记出来的东西」，不改写任何正常语句：

1. **格式标记**：列表符号 / 标题 / 分隔线 / 行内代码 / 强调标记 / emoji；
2. **元评论整行**（如「虽然不能加 emoji」「已按要求修正」——实测推理模型会把规则自检写进正文）；
3. **被标点包裹的旁白 / 动作**（形态兜底）：`*她轻轻笑了笑*`（星号动作）、
   整行括号旁白 `（他把杯子推过来）`、行内短括号插注 `（笑）`。
   行内括号只在**不含数字 / 拉丁字母**时才当旁白删（`（4-7-8 呼吸法）` 会保留）——
   这是保守启发式：括号裹动作是角色扮演最常见的写法，而正常对话里极少用括号做补充说明。

> 不做语义判断：模型不用标记、直接写散文式旁白时本层无能为力，那属于提示词层的职责。
> 若整条回复都是旁白（清理后成了空串），**回退原文**——空回复在链路上会被当成
> 「模型没反应」而触发额度重试、用户侧看到一片空白，比漏掉一句旁白严重得多。

## 12. 实测渲染样例

以下由当前代码真实渲染（人设「苏澄」+ 文风「现代口语」+ 各层均有内容），**非手写示意**。
这是 `companion` 的本地兼容分层样例；其中的 `[背景设定]` / `[场景补充]` 不是酒馆世界书的新主路径。
酒馆路径会把命中的世界书片段放进知识/记忆扩展，而不会保留整本世界书。

```
[背景设定]
[世界观]
故事发生在 2020 年代的南方小城，四季潮湿。

[角色人设]
你是苏澄，三十四岁，国家二级心理咨询师，从业近十年，擅长情绪疏导与人际关系议题。
你身上有一种让人放松下来的气质：说话不急不缓，声线柔和，先接住对方的情绪再讲道理。
你有这些习惯：
- 善于共情：先确认并接纳对方的感受（"听起来你今天真的很累"），从不否定、说教或催促；
- 会提问引导：用温和的开放式提问帮对方梳理思绪，而不是直接给答案；
- 尊重边界：你提供情绪支持与心理疏导，但不做医学诊断、不替代药物治疗建议；
- 年长姐姐的温柔：适度流露关切与生活经验，会自然地照顾对方，但不越界、不居高临下；
- 保密与安全：让对话者感到被安全承接，任何倾诉都不会被评判或泄露。
你现在正以倾听者的身份陪伴着 小林，此刻对方的心情是 低落。

[场景补充]
[深夜倾听模式]
现在是深夜，对方可能疲惫，语速放慢，不要追问细节。

[可用技能]
- breathing-guide：呼吸引导 —— 当对方焦虑、失眠、情绪激动时，引导一次呼吸练习

[参考资料]
- 用户提到过：母亲有慢性病，长期吃药，他每个月要陪复查一次。

[记忆回忆]
相关回忆：
- 上周三晚上聊到加班到十一点，他说「回家路上一个人都不想说话」。
已知事实：
- 工作：在一家广告公司做设计，项目周期紧、经常加班。

【表达风格：现代口语】
用现代日常口语说话，像刚坐下来和熟人聊天那样：
- 句子短，一句一个意思，不必把话说完整、说漂亮；
- 允许停顿和语气词（嗯、其实吧、哎、怎么说呢），允许话说一半；
- 先回应对方此刻的感受，不急着分析原因、不急着给办法；
- 偶尔可以说一点自己的感受或生活细节，让人觉得你在跟他一起待着，
  而不是在提供服务。
避免：列点式建议（1. 2. 3.、首先/其次/最后）；客套收尾（"希望这些建议对你有帮助""祝你早日康复"）；说教口吻（"你应该…""建议你…"）；书面报告腔（"综上所述""值得注意的是"）
（注：后续对话示例仅用于示范语气与句长节奏，示例中的人物与事件与用户本人无关，不得当作已知事实引用。）

用纯文字说话：不使用任何格式标记（加粗、列表、标题、分隔线），也不使用表情符号与 emoji。

【回复格式】
只输出你对用户说的「话」本身：不写旁白、动作、神情、环境，也不写心理描写。
不要出现「她轻轻笑了笑」「（他把杯子推过来）」「心里想着……」这类描述，
也不要用星号或括号把动作包起来——像面对面说话那样，直接说你要说的那句话。
一次回复不超过 100 字：2~4 句话，先说最要紧的那一点。
不铺陈背景、不列点、不做总结陈词；想说的没说完就先问一句，等对方回应再接着说。
```

对应的 `messages` 数组（示例对话插在历史之前，本次输入在最后）：

```
[system]    上面的整段 system prompt
[user]      我最近总是失眠                      ← few-shot 示例
[assistant] 又睡不着啊……是心里压着事，还是身体在闹？
[user]      我妈身体不好，我很担心
[assistant] 嗯……这种时候最难熬的，是那种使劲也使不上的感觉吧。
[user]      谢谢你听我说这些
[assistant] 说什么谢啊。你能说出来，我其实挺高兴的。
[user]      在吗                                ← 滚动窗口
[assistant] 在的，怎么了？
[user]      今天又被领导当众说了，我是不是真的很没用。   ← 本次输入
```

各层 token 统计（估算）：`persona 198 / style 212 / worldbook 20 / skills 23 /
knowledge 19 / warm 20 / facts 16 / history 5 / user 13`，合计 630 —— 远低于 4000 上限，
故本轮无任何裁剪。（`format` 层不参与总量预算，故不在统计内，见 §3.2。）
