# 记忆层架构（Memory Architecture）

> 面向：HyPRA 记忆体系的设计说明与实施路线
> 用途：参赛「项目说明」的记忆层章节底稿 + 开发实施对照
> 状态：线 A 已全部落地（混合检索 / 链路统一 / 移除摘要层 / LLM 抽取与事实状态机 /
>       记忆淘汰 / 写入异步化）；个人记忆（知识库）层为设计待实现

---

## 一、设计框架：为什么用认知心理学分层

多数对话系统的「记忆」只有一种形态：把历史消息塞回上下文。当上下文装不下时，就粗暴地截断最旧的部分——结果就是「AI 越聊越像陌生人」。

HyPRA 的选择是**按人类记忆的功能分工来分层**，而不是按工程存储类型（内存 / 向量库 / SQLite）来分。这样做的直接好处是：**每一层都有不可替代的职责**，能回答「为什么不能只用一层」这个必然会被追问的问题。

| 层 | 认知对应 | 回答的问题 | 不可替代性 |
|---|---|---|---|
| 工作记忆 | Working Memory | 「刚才说了什么」 | 逐字精确（语气、用词、称呼） |
| 情景记忆 | Episodic Memory | 「我们一起经历过什么」 | 全时段覆盖 + 按线索检索 |
| 语义记忆 | Semantic Memory | 「你是谁」 | 稳定属性常驻，不随时间流逝 |
| 个人记忆 | Personal Memory | 「你给过我的资料」 | 用户主动提供，非对话产生 |

四层之上是**统一的混合检索底座**（BM25 + 稠密向量 + RRF 融合），以及**统一的分层注入与预算裁剪**（PromptManager）。

> **合规声明**：本项目借鉴 SillyTavern 的提示词工程与记忆体系**思想**，底层代码与提示词 100% 原创。
> 具体机制参照见 [`sillytavern-memory-design-reference.md`](sillytavern-memory-design-reference.md)。

## 二、四层记忆

### 2.1 工作记忆（Working Memory）

| 项 | 内容 |
|---|---|
| 载体 | 会话内存（`session.ChatTurn` 列表） |
| 内容 | 最近 N 轮的**原文** |
| 写入 | 每轮追加 |
| 召回 | 全量传入，由 PromptManager 按 token 预算从**尾部**取（保留最近） |
| 遗忘 | 滑出预算窗口即丢 |
| 预算 | 700 tokens |

职责：保证对话的**连贯性与语气一致性**。这是唯一逐字保留原文的层。

### 2.2 情景记忆（Episodic Memory）

| 项 | 内容 |
|---|---|
| 载体 | Qdrant 向量库（本地 Docker / 云双模式）/ 内存实现 |
| 隔离 | 每个陪伴对象独立 collection：`memory_{companion_id}` |
| 内容 | 每轮用户的**原话**（`user_text`）+ 时间戳 + 情绪标签 |
| 写入 | 回复完成后事件驱动 |
| 召回 | **BM25 + 稠密向量 → RRF 融合** → 时间衰减 → 情绪加权 → top 3 |
| 遗忘 | `last_recalled_at` 超过 180 天未被召回 → 删除 |

**两个情感陪伴特有的设计**（通用 RAG 框架里通常没有）：

1. **时间衰减**：`score = 相似度 × 0.5^(age_days / 30)`。旧记忆让位于近期主线，30 天前的记忆权重减半。
2. **情绪加权**：当前情绪与记忆的情绪标签一致时，召回分 ×1.25。
   实现「此刻焦虑 → 更容易想起过往焦虑相关的片段」。

> 这两点与「个人记忆」层形成**刻意对比**：后者不做衰减、不做情绪加权——因为知识是客观的，不随时间和心情变化。

### 2.3 语义记忆（Semantic Memory）

| 项 | 内容 |
|---|---|
| 载体 | SQLite 事实表（每个陪伴对象一张表） |
| 内容 | **结构化三元组**：`subject + predicate + object` |
| 类型 | `identity` / `preference` / `relationship` / `event` / `emotion_pattern` / `ongoing` / `other` |
| 写入 | 回复完成后由 **LLM 抽取器**事件驱动抽取 |
| 召回 | 固定注入 top 3 高 `importance` 锚点 + 按 query 检索 top 2 相关 |
| 遗忘 | **状态机**（不用时间淘汰）+ 低价值记录物理归档 |

**与情景记忆的本质区别**：

- 「上周二我和我妈吵架了」→ **情景**（带时间情境的具体经历）
- 「我妈有高血压」→ **语义**（抽掉情境后剩下的稳定属性）

字段设计围绕三条意图：

| 字段 | 意图 |
|---|---|
| `importance` (1–5) | `>= 4` 视为**长期锚点**，常驻 prompt 防止人设崩塌 |
| `status` (ACTIVE/STALE/RESOLVED) | **事件闭环**：事情过去了就不再提示 |
| `confidence` + `last_seen_at` | 被反复印证的事实可信度递增 |

**状态机**（存储层已具备，转换由抽取链路触发）：

| 状态 | 语义 | 触发条件 |
|---|---|---|
| `ACTIVE` | 当前为真，参与召回 | 新抽取 / 被再次印证（`touch`） |
| `STALE` | **被新信息取代** | ① 语义：同 `subject+predicate` 出现新 `object`（换工作、搬家）<br>② 时间：`ongoing`/`event` 类超过 30 天未被印证 |
| `RESOLVED` | **事件终结**（不是被否定，而是完成了） | 事件有明确结局（「和老板谈加薪」→「谈成了」） |

转换触发者的**分工原则**：

| 判断 | 执行者 | 理由 |
|---|---|---|
| 完全相同的三元组 → 不新增，改为 `touch` | **规则** | 零成本、零误判、可单测 |
| 语义冲突 → `STALE` | **LLM** | 需要语义理解 |
| 事件闭环 → `RESOLVED` | **LLM** | 需要语义理解 |
| 进行中事项超期 → `STALE` | **规则** | 纯时间判断 |

### 2.4 个人记忆（Personal Memory）

| 项 | 内容 |
|---|---|
| 载体 | 与情景记忆同一套底座，独立 collection：`knowledge_{companion_id}` |
| 内容 | 用户**主动上传**的文档（txt / md / PDF / Word） |
| 写入 | 用户上传 → 解析 → 清洗 → 去重 → 分块 → 向量化 |
| 召回 | **与情景记忆完全相同的混合检索策略**（BM25 + 向量 + RRF），但**不做时间衰减、不做情绪加权** |
| 遗忘 | 用户主动删除 |

**处理流水线**：

```
上传 → ①解析(格式适配) → ②清洗去噪 → ③去重 → ④分块 → ⑤向量化 → ⑥入库
```

| 阶段 | 做法 |
|---|---|
| **解析** | `pypdf`（PDF）/ `python-docx`（.docx）/ 原生（txt、md）。扫描版 PDF 无文字层时**明确报错**，不静默入库空文档 |
| **清洗** | 正则 + 归一化：控制与零宽字符、PDF 页眉页脚与页码、Word 残留、HTML 标签、空白归一；**保留 Markdown 标题结构**（分块需要） |
| **去重** | 三级：文件字节 MD5 → 清洗后内容 MD5 → **MinHash**（近似重复）。命中返回 409 + 相似文档信息，需 `force=true` 才覆盖 |
| **分块** | 四级递归降级（标题 → 段落 → 句子 → 子句）+ **语义边界**（相邻句向量余弦低于阈值处提前切分）+ **句级 overlap** |

分块策略的关键取舍：**递归切分保证长度可控，语义相似度决定在哪里「提前」切**——两者互补而非竞争。纯语义分块不保证块长可控（可能切出碎片或巨块）。

## 三、统一的混合检索底座

情景记忆、个人记忆、以及语义记忆的**冲突检测**共用同一条检索链路：

```
query
 ├─ 稠密通道  embedding → 向量检索   top_n = 10  ─┐
 └─ 稀疏通道  jieba 分词 → BM25      top_n = 10  ─┤
                                                  ↓
                                   RRF 融合  Σ 1/(60 + rank)
                                                  ↓
                        （仅情景记忆）时间衰减 × 情绪加权
                                                  ↓
                                              top_k = 3
```

**为什么用 RRF（Reciprocal Rank Fusion）而不是加权求和**：

RRF 只依赖**排名**，不依赖分数尺度。余弦相似度（0~1）与 BM25 分数（0~∞）量纲完全不同，加权求和需要归一化与人工调参；RRF 天然回避了这个问题。

**阈值策略**：相似度阈值**下沉到融合前的稠密通道**。因为 RRF 分数只有相对排名含义，融合后无法施加绝对阈值。

**稀疏通道的价值**（不只是精度提升）：

- 专有名词、人名、编号等**字面精确匹配**场景，向量检索容易漂移，BM25 稳定
- **BM25 不受时间衰减影响** → 老记忆只要关键词命中就能被重新召回，从而刷新其 `last_recalled_at`，避免被淘汰机制误杀

**世界书的注入不走 RRF**：它是「关键词 ∨ 正则 ∨ 语义向量」的**多通道并行触发**（任一命中即注入），配无条件阈值（`vector_threshold`，经实测校准），本质是「规则 + 语义的混合触发」而非分数融合。

## 四、写入链路

```
generate_reply → 回复返回用户
                    ↓（异步执行，用户无感知延迟；按 companion_id 串行化）
              LLM 抽取器
                    ├─ 输入：本轮对话 + 混合检索召回的相关事实
                    ├─ 新事实 → 规则去重（三元组相同 → touch，confidence += 0.1）
                    ├─ 状态指令 → update_status(stale / resolved)
                    └─ 关键词
                    ↓
        语义记忆（SQLite 事实表）  +  情景记忆（向量入库）
                    ↓
        生命周期维护：
          · 惰性检查：ongoing/event 类超期 → STALE
          · 启动时检查：情景记忆 last_recalled_at > 180 天 → 删除
          · 定期归档：STALE/RESOLVED 且 importance ≤ 3 且 > 90 天 → 物理删除
```

**为什么异步**：抽取在回复生成之后，用户已经拿到回复，因此可以放到后台；LLM 抽取的 1–3 秒延迟对用户不可见。代价是同会话并发写入需要串行化。

**降级**：LLM 抽取失败时回退到规则抽取器，记 warning，不阻断对话。

## 五、PromptManager 分层注入与预算

固定优先级（高 → 低）与两级预算裁剪：

| 层 | 优先级 | 预算 (tokens) | 截断方向 |
|---|---|---|---|
| 角色人设 | 100（必留） | — | 永不裁剪 |
| 本次输入 | 100（必留） | — | 永不裁剪 |
| 表达风格 | 90 | 400 | 尾部 |
| 世界书命中 | 80 | 400 | 尾部 |
| **个人记忆** | 70 | 900 | 尾部 |
| 情景记忆（召回） | 60 | 300 | 逐条装入 |
| 语义记忆（事实） | 55 | 450 | 逐条装入 |
| 工作记忆（窗口） | 20 | 700 | **保留最近** |
| **总量** | | **4000** | |

裁剪顺序（总量不足时）：先丢工作记忆的最旧消息 → 再从最低优先级层开始整层清空。

**为什么总量提到 4000**：原先 2000 的设定对现代模型（Qwen2.5-7B 支持 32K 上下文）过分保守，导致各层长期互相挤压。扩容后各层基本能装下，不再互相饿死。

## 六、生命周期管理

| 层 | 淘汰机制 | 阈值 |
|---|---|---|
| 工作记忆 | 滑出 token 预算 | 700 tokens |
| 情景记忆 | `last_recalled_at` 超期 | **180 天** |
| 语义记忆 | 状态机（`STALE`/`RESOLVED` 不召回）+ 低价值归档 | 归档条件：`importance ≤ 3` 且 > 90 天 |
| 个人记忆 | 用户主动删除 | — |

**情景记忆的淘汰用「最近被召回时间」而非「创建时间」**——一条记忆是否有价值，取决于它是否仍在被需要，而不是它有多新。

⚠️ **与时间衰减的耦合风险**：时间衰减会让老记忆难以进入 top 3，从而不被召回、时间戳不刷新、最终被删除——形成正反馈。三个缓解手段：

1. 淘汰 TTL（180 天）**远大于**衰减半衰期（30 天），留出 6 倍的重新召回窗口
2. **BM25 通道不受衰减影响**，为老记忆提供第二条被召回的路径
3. 候选集按原始相似度选取，衰减只作用于最终排序

## 七、参数总表

### 检索

| 参数 | 值 | 说明 |
|---|---|---|
| RRF `k` | 60 | 标准值 |
| 各通道候选 `top_n` | 10 | 融合前 |
| 最终 `top_k` | 3 | 融合后 |
| 情景记忆衰减半衰期 | 30 天 | `0.5^(age/30)` |

## 八、对参赛评审维度的贡献与边界

| 维度 | 贡献 |
|---|---|
| **智能交互深度（25%）** | 混合检索 + 完整索引链路 + 记忆生命周期管理；对应评分点原文「记忆与个性化（上下文记忆/RAG/个性化）」 |
| **产品完成度（25%）** | 多层降级与容错（任一层不可用不阻断对话） |
| **场景创意与价值（35%）** | ⚠️ **不构成贡献**——RAG 在纯文本对话框中同样可实现，本节内容**不用来论证具身不可替代性**（该论证见 [`why-embodied-avatar.md`](why-embodied-avatar.md)） |

**边界声明**：记忆层是「智能交互深度」的技术支撑，不是「具身不可替代性」的论据。参赛文档中两者分开陈述，避免论证注水。

## 附录：设计演进记录

以下问题在架构评审中被识别并已纳入实施计划，记录在此以备追溯：

| 编号 | 问题 | 处理 |
|---|---|---|
| P1 | 事实召回「先截断后排序」导致高重要度事实被漏 | 排序键下沉到 SQL |
| P2 | 情景记忆无相似度阈值，无关输入也会注入记忆 | 阈值下沉到融合前 |
| P3 | 衰减参数硬编码 | 暴露为配置项（**已落地**） |
| P4 | 两套存储后端的候选集策略不一致 | 统一候选倍数 |
| P5 | `to_prompt_block` 已无调用点；配置项命名与作用不符 | 清理并改名 |
| P6 | 事实召回与当前输入完全无关 | 锚点 + 相关性混合召回 |
| P7 | 摘要层与工作记忆职责重叠、且反向截断 | **已移除该层**（职责由情景记忆与语义记忆分担） |
| C1 | 事实状态机从未被触发 | 由抽取链路接通（**已落地**） |
| C2 | `importance` 按类型硬编码，锚点机制失效 | LLM 按内容评分 + `confidence` 累积（**已落地**） |
| C6 | 规则抽取器覆盖率低 | 接入 LLM 抽取器，规则版保留作降级（**已落地**） |
| C7 | `emotion_pattern` 类型无抽取来源 | 明确边界：只存跨轮稳定模式，单次情绪走情绪日记 |
