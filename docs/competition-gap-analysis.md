## 一、赛题要点（原文提炼）

### 1.1 命题背景

> 「AI 应用的交互形态却仍显『抽象』：大部分产品停留于文本对话框或单向语音播报，缺乏形象、表情与肢体表达，难以传递温度与信任感。」

> 「具身智能正成为 AI 走向产业与大众的关键方向——AI 的表达从『文本』升级为『3D 多模态』，让智能体不仅『会说话』，而且『有形象、会表达、能行动』。」

> 「传统开发手段……大多也只是文本和虚拟形象的简单拼接；还容易出现设备展示效果参差不齐，语音、表情、动作时序错位脱节。」

### 1.2 命题目标

基于 **魔珐星云具身交互智能体 SDK（XmovAvatar）** 开发一套具身交互智能体应用；应用场景不限，鼓励「人格化的 AI 交互」原创构想。

三个自由度（**作品至少覆盖表达层**）：

| 自由度 | 定位 | 可选纵深 |
|---|---|---|
| **表达层** | 有温度的多模态呈现界面 | TTS/SSML 语音播报、流式分段播报、字幕、形象与音色配置 |
| **交互层** | 可双向沟通的对话载体 | 接入任意大模型、RAG 知识问答、多轮对话、情绪匹配、聆听与打断 |
| **行动层** | 可执行任务的 Agent 载体 | 工具调用（Function Calling / MCP）、行走与动作编排、多模态 Widget |

参考方向：知识服务型 / 效率助手型 / 普惠无障碍型 / 前沿探索型。

> **核心加分项**：「需要论证该业务场景下，具身交互智能对比纯文本/纯语音方案的**不可替代价值**，解释为什么该场景需要多模态双向交互，而不是只用对话框就可以完成。」

### 1.3 交付要求

1. 项目说明（技术架构、创新点、价值）
2. 开源代码（Gitee/GitHub + Apache 2.0 / MIT）
3. 构建部署方法（**建议 Docker Compose**，评审可直接运行验证）
4. 演示视频（建议 3–5 分钟，端到端流程）

> ⚠️ **许可范围待确认**：赛题此条列举的是 Apache 2.0 / MIT，而本项目以 **AGPL-3.0** 发布。
> 需向主办方确认 AGPL 是否被接受；结论须回写 `docs/license-compliance.md`（见该文件 §1）。
